Personal Technical Glossary

Definitions are written in the way I currently understand and use the terms. They are not intended to replace formal definitions.

AI / ML

AI system — The whole system around a model: interface, application logic, context, memory/state, tools, evaluation and feedback.

Model — A trained computational model that maps inputs to outputs; in an AI application, it is one component rather than the entire system.

LLM — A language model that predicts/generates text and related representations; useful as a reasoning/language component but not automatically reliable.

Inference — Using a trained model to produce an output from new input.

Context — Information supplied to a model that influences its current output.

Memory — Persistent information retained across interactions or steps so that the system can maintain state.

State — The information representing what the system currently believes/knows about the user, task or environment.

Tool use — Giving a model access to external capabilities such as search, code, APIs or other systems.

Agent — A system that can repeatedly interpret a goal, choose actions/tools, observe results and continue rather than producing only one response.

Grounding — Constraining model outputs using external information, data or evidence.

Retrieval — Finding relevant information from an external knowledge source for use by the model.

Evaluation — A defined method for determining whether a system's output or behavior actually satisfies the objective.

Verification — Checking generated work against requirements, tests, evidence or another trusted criterion.

Reliability — How consistently the system behaves correctly enough for its intended use.

Learning systems

Adaptive learning — A system changes content, difficulty, explanations or interventions based on information about the learner.

Learner model — A representation/estimate of what a learner currently knows, misunderstands or is ready to learn next.

Scaffolding — Temporary support that helps a learner perform a task they cannot yet perform independently.

Fading — Gradually removing scaffolding as competence increases.

Graduated prompting — Starting with a minimal cue and escalating support only when needed.

Hint — A targeted intervention intended to move the learner forward without completing the task for them.

Minimum sufficient hint — The smallest intervention likely to get the learner unstuck while preserving the important cognitive work.

Productive confusion — Uncertainty or difficulty that still leaves the learner able to think, attempt, compare and learn.

Unproductive confusion — Confusion that prevents useful progress or is caused by missing prerequisites/poor explanation.

Information load — The amount and complexity of information presented to the learner at a given point.

Transfer — Ability to apply a learned concept to a new problem/context rather than reproducing the original example.

Systems / engineering

Feedback loop — A system observes the result of an action and uses that information to choose or modify the next action.

State estimation — Inferring an unobserved state from available measurements/behavior.

Pipeline — A sequence of processing stages where the output of one stage becomes the input of the next.

Abstraction — Hiding implementation detail so a reusable concept/interface can be reasoned about more easily.

Architecture — The high-level structure and relationships between system components.

Integration — Combining existing components so that their interaction produces a useful capability.

Prototype — The smallest practical version of a system used to test an idea, assumption or user need.

Experimental instrument — A prototype built mainly to produce evidence about a research question.

Automation — Turning a repeatable process into a system that performs some steps with reduced manual effort.

Human-in-the-loop — A system where a person remains part of the decision/control process.

Computer vision / HCI

Computer vision — Using computation to extract information from images/video.

Pose estimation — Estimating body/joint positions from visual input.

Motion tracking — Tracking changes in body/object position over time.

Gesture interface — Using physical gestures as inputs to a digital system.

HCI (Human-Computer Interaction) — The design and study of interactions between people and computing systems.

Motion-to-feedback pipeline — Movement → sensing → interpretation → feedback → changed movement.

Networking / software

API — A defined interface through which one software component can request functionality/data from another.

Client-server — A model where a client requests resources/services from a server.

DNS — The naming system that maps domain names to network addresses.

HTTP/HTTPS — Protocols used for web communication; HTTPS adds encryption/authentication through TLS.

Distributed system — A system whose components communicate across separate processes/machines.

Debugging — Finding and resolving causes of incorrect software behavior.

Testing — Running defined checks to determine whether software behaves as expected.

Research

Research question — A focused question that can be investigated using evidence.

Hypothesis — A testable proposed explanation/prediction.

Method — The procedure used to investigate the question.

Evidence — Observations/data/results that support or challenge a claim.

Contribution — What a study adds beyond what was already known or available.

Replication — Repeating a study/method to see whether the result is consistent.

Research gap — An important question or limitation that existing work does not adequately address.

My recurring project vocabulary

Project Navigator — My idea for an AI-assisted system that helps decide what to build, learn, research or pursue next.

Learning Systems Lab — A public lab notebook for experiments, prototypes and technical findings around learning and AI.

Adaptive Learning Playground — A web app for adaptive educational experiments.

Motion Learning Assistant — A computer-vision system using movement as input and feedback as output.

Capability graph — A representation of skills/capabilities and their relationships/prerequisites.

Proof-of-Build Verifier — The idea of demonstrating capability through actual artifacts/evidence rather than claims alone.
