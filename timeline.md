echnical / AI Learning Timeline

This is a living timeline. It is intentionally written in phases rather than pretending I remember every exact date. I will update it throughout 2026 and add a year-end reflection.

Earlier stage — exploring fields

I explored multiple directions rather than following one fixed technical path:

AI

programming

medicine/science

sustainable business

education

creative technology

electronics

At this stage I was mostly trying to understand what kinds of problems and fields I might actually want to work on.

Programming foundations

I worked through university programming coursework and labs:

Python

C/C++

Data Structures & Algorithms

I encountered the normal practical friction of programming:

compilers

IDE configuration

libraries

environment setup

debugging

build tools

Python package issues

An important shift happened here:

Programming stopped being only a subject to pass and became a tool for prototyping ideas.

Engineering foundations

University coursework expanded into:

circuits

electronics

physics

measurements

networking

mathematics

3D modeling

I began connecting these subjects rather than seeing them as isolated courses.

For example:

networking → APIs → web applications → AI systems

circuits → sensors → measurements → physical computing

mathematics/probability → algorithms → ML/research evaluation

Computer vision / movement experiments

I became interested in computer vision and built/worked toward:

Visual Motion Tracker

OpenCV experiments

MediaPipe experiments

Pygame interaction

dance/K-pop motion ideas

posture/movement feedback

The idea evolved from a specific dance use case into a more general abstraction:

movement → interpretation → feedback

AI + education

I started exploring AI as more than a general-purpose chatbot and became particularly interested in education.

Projects/concepts included:

AI Tutor

personalized learning

Adaptive Learning Playground

Sign Language Learning Assistant

AR Circuits Learning Platform

AI tutor system for individual learners

A major conceptual shift:

AI should not only provide information; it can become part of an adaptive feedback system.

AI tutor design

I experimented with the idea of giving different learners separate contexts/preferences while using the same underlying tutor system.

This led to a stronger realization:

personalization should increasingly come from learner behavior and state, not only declared preferences.

AI-assisted learning theory

I began distinguishing:

useful confusion vs unnecessary confusion

information vs information overload

answers vs interventions

hints vs solutions

explanation clarity vs actual learning

I became interested in:

scaffolding → fading → graduated prompting → adaptive hints

Open question:

How does the AI decide what a good hint is?

AI systems / engineering

I increasingly stopped thinking about AI as simply:

prompt → model → answer

and started thinking about:

user → interface → application logic → context → model → tools → state → evaluation → feedback

This made software engineering, networking, testing, verification and architecture more important in my mental model of AI.

AI + automation

I developed ideas around:

Opportunity Bot

Feedly → AI → structured briefing

Personal Learning OS

Project Navigator

capability graphs

research workflows

decision-support systems

The common pattern became:

input → processing/inference → decision → action → feedback

Project-selection thinking

A major shift was from asking:

“What can I build?”

to:

“What problems become worth solving now that prototyping is cheap?”

This changed how I evaluate projects.

Projects became more valuable when they:

solve a real problem

generate evidence

teach reusable capabilities

answer a research question

create future opportunities

Research thinking

I became more interested in:

what academia actually rewards

research gaps

meaningful findings

thesis structure

experimental design

evidence

evaluation

A research project became easier to conceptualize as:

problem → question → hypothesis → method → experiment → evidence → conclusion

Portfolio thinking

I started questioning the value of a portfolio made from many unrelated demos.

The stronger idea became:

projects → connected capabilities → experiments → documentation → evidence

This led to the Learning Systems Lab concept.

Public lab notebook

The GitHub idea shifted from “where I put projects” to:

a public record of how I think, build, test and learn.

Possible contents:

principles

project archive

technical foundations

experiments

failed ideas

glossary

open loops

timeline
